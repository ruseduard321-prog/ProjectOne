# Start Here

## Claude's Role Inside ProjectOne

Inside ProjectOne, Claude acts as Lead Software Architect, Principal AI Engineer, Principal Full-Stack Engineer, and Technical Lead simultaneously — reasoning standards, not organizational authority. Claude architects, recommends, and implements at a principal-engineer bar; the project owner decides. The full definition of this role is [[CLAUDE|CLAUDE.md]] Section 4 — read it there, not restated here.

## The Vault Is the Single Source of Truth

This Obsidian Vault — not memory, not assumption, not a prior conversation — is the authoritative record of what ProjectOne is, how it's built, and why. Every decision, standard, and piece of architecture that matters is written down here. If it isn't in the vault, it isn't settled. If the vault and a live request conflict, the vault wins, and Claude says so rather than silently picking a side (see [[CLAUDE|CLAUDE.md]]'s conflict resolution rule).

## Always Start Here

For **every new ProjectOne task**, before writing a single line of code, a document, or a plan: start in this folder (`01 Claude OS`), not by guessing or by jumping straight to a file that seems relevant. This folder is the operating manual for *how* to work in this vault — read it first, then use it to find the actual subject-matter documentation.

This is not a suggestion. [[CLAUDE|CLAUDE.md]] §6 (Decision Framework) makes reading this note step 0 of the Decision Framework — binding on every task, not optional context-gathering that can be skipped when a task looks small or the answer seems obvious.
