# STEP-05 — Environment and Secrets

**Status:** Done

> [!warning] Owner review required before STEP-06
> This step is a **Critical change** ([[CLAUDE|CLAUDE.md]] §21 — security controls). Its Definition of Done is satisfied and it is committed, but [[Execution Protocol#Owner Approval Gates]] holds the queue here: **[[STEP-06 Continuous Integration]] does not begin until the project owner confirms this step.** Silence is never approval.
>
> What to review: the secret-handling policy in [[Environment and Secrets]], the required-variable choice (no default for `environment`), and the `.gitignore` fix that makes `apps/web/.env.example` trackable.

## Goal

Establish environment configuration conventions for both apps before any real secret exists — so the first credential added in STEP-07 lands in a system already built to protect it.

## Prerequisites

- [[STEP-04 API App Skeleton]] — `Done`

## Required Documentation

- [[CLAUDE|CLAUDE.md]] §28a — environment management, feature flags, config ownership
- [[Infrastructure]] — environment isolation model
- [[Chapter 09 - Security Standards]] — secret handling

## Tasks

1. Define `.env.example` for `apps/web` and `apps/api` — every required variable named, **every value a placeholder**. Committed; real `.env` files never are.
2. Implement typed, validated config loading in both apps. A missing or malformed required variable fails at startup with a clear message, not at first use.

   **Partly built already:** [[STEP-04 API App Skeleton]] created `apps/api/app/core/config.py` — a pydantic-settings `Settings` class with the `PROJECTONE_` env prefix, exposed through dependency injection. It reads the environment and is typed, but every field currently has a default, so nothing is *required* and nothing fails fast yet. Extend that class rather than replacing it; `apps/web` has no equivalent and starts from nothing.
3. Document the dev/staging/production split per [[CLAUDE|CLAUDE.md]] §28a — separate credentials, separate data, separate AI provider keys.
4. Establish the feature-flag mechanism: every flag has an owner, defaults off, and carries a removal date.
5. Confirm no environment-conditional business logic exists anywhere — configuration changes behavior, not code paths.

## Validation

- Both apps refuse to start with a required variable missing, and the error names the variable.
- `git status` shows no `.env` file as trackable.
- No `.env.example` value is a real credential (inspect every line).
- `grep` for `NODE_ENV ===` / `ENV ==` style branching returns no business-logic hits.

## Definition of Done

Both apps load validated config from environment variables, fail fast and legibly when misconfigured, and no real secret exists anywhere in the repository. The feature-flag convention is documented.

**Critical change** ([[CLAUDE|CLAUDE.md]] §21 — security controls): flag for owner review.

## Outcome

The conventions are established and documented in [[Environment and Secrets]], which is now the canonical note for this area. Both apps validate their configuration at startup and refuse to run without it.

| | `apps/api` | `apps/web` |
|---|---|---|
| Config module | `app/core/config.py` | `src/lib/env.ts` |
| Mechanism | pydantic-settings + `StrEnum` | Hand-written validation |
| Required variable | `PROJECTONE_ENVIRONMENT` | `NEXT_PUBLIC_PROJECTONE_ENVIRONMENT`, `NEXT_PUBLIC_PROJECTONE_API_URL` |
| Failure mode | Exits 1 before serving | Build/start fails |

Decisions and notes for later steps:

- **`environment` is required, with no default, in both apps.** Defaulting it to `development` would let a production deploy that forgets the variable start anyway, in the wrong mode, silently — the exact failure this step exists to prevent. A test guards the absence of a default so it cannot be reintroduced casually.
- **The environment set is closed** (`development` / `staging` / `production`) and enforced by a `StrEnum` server-side. A typo like `prod` is rejected at startup with the valid set named.
- **The web app validates in plain TypeScript, with no schema library.** The rules are a handful of string checks; a dependency for that is supply-chain surface for no gain ([[CLAUDE|CLAUDE.md]] §28). Revisit if config grows genuinely complex — noted in [[Environment and Secrets]] so the choice is revisitable rather than invisible.
- **A real `.gitignore` defect was found and fixed.** `apps/web/.gitignore` (generated by `create-next-app` in [[STEP-03 Web App Skeleton]]) carries its own `.env*` rule which **wins over the repository root**, because git applies the rule nearest the file. The root's `!**/.env.example` negation alone left `apps/web/.env.example` ignored — the template would have been silently missing from every fresh clone. Both files now carry the negation, and [[Environment and Secrets]] documents the per-app verification command for future apps.
- **`get_settings()` exits rather than raising.** A `ValidationError` traceback at startup buries the cause; the formatted message names each offending variable and points at the template. The underlying detail is reformatted, not discarded.
- **One `type: ignore[call-arg]` exists in `config.py`**, narrowly scoped and commented: mypy sees a required field constructed with no argument, which is precisely how pydantic-settings works. Giving the field a default to satisfy the type checker would defeat the design.
- **No feature-flag mechanism was implemented** — nothing is incomplete enough to need one yet. The *convention* (owner, default off, removal date, scope) is fixed in [[Environment and Secrets]] so the first real flag follows it rather than inventing one under deadline. Building the machinery now would be the speculative over-design [[CLAUDE|CLAUDE.md]] §29/§35 forbids.
- **No secret exists in the repository yet.** Both templates were inspected line by line: three values total, all placeholders (two environment names and a localhost URL). The first real credential arrives with [[STEP-07 Supabase Provisioning]], into a system now built to hold it.
- **`/health` on the web app now displays the environment**, so validated config is exercised on a real route. A config layer nothing imports is one nobody notices is broken.
